## S1. Health regeneration — Gameplay "Segment regeneration UNKNOWN", Integration "RE I3 not consumed" (C)

**Who runs it:**
- `TnPawn.Tick` calls `HealthRegener.Update(dt)` only on authority (Role 3) and when the pawn is not downed.
- `HealthRegener` is initialised from `_Blueprint.HealthRegenParameters`. That blueprint is the **current form's def**, so robot and vehicle forms regenerate differently.

**`TnHealthRegener.Update`:**
- return if Health ≥ HealthMax, or RegenRate == 0;
- if the pawn has `TnBuffHealthRegenKillStreak`: heal type `TnHealTypeRegenAll`, and the delay is skipped;
- otherwise:
  - heal type `TnHealTypeRegen`;
  - `TimeSinceRegenInterrupted += dt`;
  - pastDelay = TimeSinceRegenInterrupted − RegenDelay (× `RegenDelayModifier`);
- if pastDelay > 0: `HealDamage(RegenRate (× RegenRateModifier) × min(dt, pastDelay), none, HealType)`.

**Interrupt:** `TnPawn.TakeDamage` → `HealthRegener.InterruptRegen()` (timer = 0) on **every** damage event.

**Cap:**
- `TnHealTypeRegen.SegmentedHealType = SHT_HealSegment` → `TnSegmentedHealth.AddHealthToSegment`. That gives min(amount, subtotal(ServerActiveSegment) − Health), so **regen only refills the current segment**.
- `TnHealTypeRegenAll` (killstreak) uses the default, `SHT_HealAll` → `AddHealthToAll`, which can cross segments.
- `ServerActiveSegment` is recomputed after every damage event (`TnPlayerPawn.TakeDamage` → `ResetActiveSegment`) as the segment containing Health. Health exactly on a boundary belongs to the lower segment, so a full lower segment does not regen into the next one.

**Data** (authored ROBODEF / VEHDEF `HealthRegenParameters`, every player character):

| Form | RegenRate | RegenDelay |
|---|---|---|
| Robot | **20 HP/s** | **2.0 s** |
| Vehicle | **12 HP/s** | **7.0 s** |
| Soldier-car minions | 15 | 5 |

**Correction reminder:** MP health is the **specialty** health (pass 3 §A4: `Health_Scout` 4×50, `Health_Scientist` 3×60, `Health_Soldier` 6×55, `Health_Leader` 5×60, overshield 200), not `SharedHealth` 550. Gameplay FIDELITY still says SharedHealth.

**Friendly fire** (C, `TnPlayerPawn.TakeDamage`): damage from a teammate is dropped with only `NotifyHitByFriendlyFire`. This also applies to damage from one's own sentry and to damage from **another** controller on the same team. The only exception is a damage type exactly `TnDamageTypeAOE`, which goes through. Self-damage is not filtered.

## S2. Spawn point inside the active cluster — Gameplay "which start is picked UNKNOWN / IsSafeSpawnLocation approximated as 4 m" (C)

**`TnSpawnPointManager.FindSpawnPoint`:**
- uses the controller team's **active cluster**;
- up to `MaxSpawnPointsToConsider` **4** times: NP = `Cluster.GetSpawnPoint()`, then `LocationValidator.IsSafeSpawnLocation(NP.Location, NP cylinder R, H)`; the first safe one wins;
- if none of the 4 is safe it returns none. `TnTeamGame.FindPlayerStart` then falls back to the stock `FindPlayerStart` / `RatePlayerStart` (team-filtered `TnTeamPlayerStart`, −1 for the wrong team).

**`TnSpawnCluster.GetSpawnPoint`** is a **round-robin** iterator over the cluster's `SpawnPoints` (it wraps to 0). It persists across calls, so consecutive spawns rotate through the cluster. `SpawnPoints` = every `TnTeamPlayerStartBase` inside the cluster volume, sorted by actor iteration (editor `PreSave`).

**`IsSafeSpawnLocation`** is native:
- exec `0x829F7A28` (static native table entry `0x83708FA0` → `0x829F7A28`) → `0x829EF778`.
- **Box overlap check**, `MultiPointCheck`-shaped `0x82C0E450`:
  - centre = Location + (0, 0, 0.5·H);
  - extent = (R, R, 0.5·H), so the box spans Z from Location to Location + H;
  - trace flags `0x080022BF`: Pawns, Movers, Level, Volumes, Others, 0x20, LevelGeometry, StopAtAnyHit, Terrain.
- Safe ⇔ **no overlap at all**. Any pawn, mover, blocking volume or world geometry inside the start's cylinder box blocks the start; there is no distance radius.
- Debug draw: green when clear, red when blocked.

The manager CDO also sets ActiveClusterTime 10, EarlyCutoffScoreDifference 5, UpdateInterval 0.1 and InitialSpawnTime 15. These match Gameplay's CONFIRMED cluster scoring.

**Tombstone** (cluster modifier −5/d): `Default__TnTombstone.LifeSpan` **8.0 s** (C). It is spawned for each `TnPlayerController` death at the pawn location, team = victim team.

## S4. KOTH zone rotation — Gameplay "what triggers KOTH rotation UNKNOWN" (C)

**Start:**
- `MatchStarting` on the first zone to initialise: index = `RandRangeInt(−1, AllOtherZones.Length)`; −1 = this zone. The chosen zone `Activate()`s, the rest `Deactivate()`.
- Announcer is ignored for `AnnouncerMatchStartHysteresisTime` **3 s**.

**`Activate`:** ActiveTimeLeft = `ZoneActiveTime` **60**, PeriodTimeLeft = `ScoreInterval` **1.0**, state Active.

**`Active.BeginState`:**
- shown;
- `MP_HillMovedDialog`;
- `UpdateClaim(true)`;
- objective marker "Active Node";
- message 3;
- attach `SpawnModifier` (rule CutoffDistance 5000, Factor −50).

**`Active.Tick`:**
- `UpdateClaim(false)` every tick:
  - one living team inside → that team;
  - mixed → 254 (contested);
  - none → 255;
  - `SetTeam` fires `DefendingTeamChanged`.
- Every 1.0 s `ScoreZone`, only if the defender is 0 or 1: each **living** pawn of either team inside gets `Game.ScoreObjective(PRI, PointsPerInterval 1)` plus per-player zone score.
- When ActiveTimeLeft ≤ 0, `ActivateNewZone`:
  - random pick among other zones not yet active this cycle;
  - when all have been active, reset the flags and pick any other zone at random;
  - the current zone deactivates.
- `EndState`: flush `AddZoneScore` per player.

**`DefendingTeamChanged`:**
- announcer: `MP_HillCapturedAutobot` / `Decepticon` / `Contested` / `Neutral` (suppressed during the activation);
- the `ActiveMesh` colour param = `CaptureColor[team]` (Autobot `(0.73, 0.13, 0.13)`, Decepticon `(0.27, 0.19, 0.76)`) or `NeutralColor`;
- message 0 / 1 / 2.

**End:** `TnGameRules_ScoreKingOfTheHill.CheckEndGame` deactivates every zone.

## S5. End-of-match result text and announcer — Integration "TnVersusGameOverMessage PARTIAL", Gameplay "FFA result text not read" (C)

- **1 tie** if there is no winner;

- **0 normal** otherwise.

**`TnVersusGameOverMessage.ClientReceive`:**

## S7. GFx view scale mode and viewport — Rendering / Frontend title-vignette question

**C:**
- `UGFxMovie::execStart` `0x82A24770` → `0x82A240C8` → load `0x82A23DC8` → view setup `0x82A1FF08`. The view is held at movie+0x34.
- The view setup calls view vtable +0x68 (SetViewport), +0xD0(1), +0xA0 and +0x90. It **never calls +0x70 (SetViewScaleMode)** and makes no alignment call.
- +0x70 identity: the Stage.scaleMode AS setter `0x831EB298` maps the strings noScale/exactFit/noBorder/showAll to 0/2/3/1 and calls +0x70; the getter is +0x74.
- Window viewport:
  - buffer = viewport client SizeX/SizeY;
  - rect = (0, 0, SizeX, SizeY), i.e. the **full viewport, no 14:9 or safe-area rect**;
  - Scale 1.0;
  - AspectRatio = pixel aspect / (SizeX/SizeY);
  - flags 4.

**H:** the mode is therefore Scaleform's MovieRoot default (SM_ShowAll, Align_Center in Scaleform 3.x).
- Hud_GFX overrides it to noScale in its own ActionScript.
- FrontEnd_GFX does not override it.
- The constructor default store itself was not pinned in the binary.
